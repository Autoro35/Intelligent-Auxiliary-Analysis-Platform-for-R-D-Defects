## 三、快速开始

### 方式一：Docker 一键启动（推荐）

前置：已安装 Docker Desktop。

```bash
cp .env.example .env          # 按需修改端口与密钥
docker compose up -d --build  # 首次构建约 3-5 分钟
docker compose logs -f backend
```

启动后访问 **http://localhost:8888**，账号 `admin` / `admin123`。

停止与清理：

```bash
docker compose down       # 停止，保留数据
docker compose down -v    # 停止并清空数据（含数据库、附件）
```

> 对外端口刻意避开本机默认端口（MySQL 用 3307、Redis 用 6380、前端用 8888），
> 避免与本机已安装的同名服务冲突。需要调整就改 `.env`。

### 方式二：本地开发

前置：JDK 17+、Maven、Node.js 18+、MySQL 8.0。

```bash
# 1) 初始化数据库（脚本自带 CREATE DATABASE）
mysql -uroot -p < backend/sql/schema.sql

# 2) 启动后端（8080）
cd backend
mvn -DskipTests package
java -jar target/defect-platform-1.0.0.jar
# 数据库密码非默认值时：DB_PASSWORD=你的密码 java -jar target/defect-platform-1.0.0.jar

# 3) 启动前端（5173，已配置 /api 代理到 8080）
cd frontend
npm install
npm run dev
```

浏览器打开 **http://localhost:5173**。

> Redis 与 RabbitMQ **不是本地开发的必需项**：Redis 不可用时缓存自动跳过，
> 业务功能完全不受影响。

## 四、账号与角色

首次启动时后端会自动创建管理员账号（已存在则跳过），配置项 `init.admin.*`。

| 角色 | 编码 | 权限范围 |
|---|---|---|
| 管理员 | `ADMIN` | 全部功能，含用户管理、AI 状态自检、向量索引重建 |
| 测试 | `TESTER` | 项目 / 缺陷 / 知识库读写，全部 AI 能力 |
| 开发 | `DEVELOPER` | 项目 / 缺陷 / 知识库读写，全部 AI 能力 |
| 访客 | `GUEST` | 只读（项目 / 缺陷 / 知识库 / 统计），可用 RAG 推荐 |

**默认账号：`admin` / `admin123`**（生产环境务必通过 `ADMIN_PASSWORD` 覆盖）

> 自助注册接口 `/api/auth/register` 按规格保留，但**前端登录页不暴露入口**。
> 原因：注册出来的账号固定为访客角色，且无法自助升级。
> 需要新增成员时，请用管理员登录后在「用户管理」页点「新建用户」，可同时指定角色，一步到位。

**角色变更后需用户重新登录**：角色编码写入 JWT，旧令牌在过期前仍按原角色鉴权。

## 五、配置说明

所有配置集中在 `backend/src/main/resources/application.yml`，均支持环境变量覆盖，无硬编码。

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `SERVER_PORT` | `8080` | 后端端口 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `localhost` / `3306` / `defect_platform` | 数据库连接 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `123456` | 数据库账号 |
| `REDIS_HOST` / `REDIS_PORT` | `localhost` / `6379` | 缓存，不可用时自动降级 |
| `JWT_SECRET` | 内置默认值 | **生产必须更换**，长度 ≥ 32 字节 |
| `JWT_EXPIRATION` | `86400` | 令牌有效期（秒） |
| `UPLOAD_DIR` | `./uploads` | 附件存储目录 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / `admin123` | 初始管理员 |
| `DEEPSEEK_API_KEY` | 空 | 留空则 AI 降级为本地规则引擎 |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | `https://api.deepseek.com` / `deepseek-chat` | 大模型接入点 |
| `CHROMA_HOST` / `CHROMA_PORT` | `localhost` / `8000` | 向量库，不可达则降级为全文索引 |
| `CHROMA_API_PATH` | `/api/v2` | Chroma 0.5+/1.x 用 `/api/v2`，0.4.x 改 `/api/v1` |

## 七、缺陷状态机

```
NEW(新建) ──ASSIGN──> ASSIGNED(已分配) ──START──> PROCESSING(处理中)
                                                      │
                                                  RESOLVE
                                                      ↓
                                              PENDING_RETEST(待复测)
                                                      │
                                        ┌─────────────┴─────────────┐
                                      CLOSE                      REJECT
                                        ↓                           ↓
                                  CLOSED(已关闭)              REJECTED(已驳回)
                                                                    │
                                                                REOPEN
                                                                    ↓
                                                          PROCESSING(处理中)
```

| 当前状态 | 可用动作 | 目标状态 | 必填参数 |
|---|---|---|---|
| `NEW` | `ASSIGN` | `ASSIGNED` | `assigneeId` |
| `ASSIGNED` | `START` | `PROCESSING` | — |
| `PROCESSING` | `RESOLVE` | `PENDING_RETEST` | `solution` |
| `PENDING_RETEST` | `CLOSE` | `CLOSED` | — |
| `PENDING_RETEST` | `REJECT` | `REJECTED` | — |
| `REJECTED` | `REOPEN` | `PROCESSING` | — |

前端 [enums.js](../frontend/src/constants/enums.js) 中的 `DEFECT_TRANSITIONS` 与后端状态机严格对应，按钮按当前状态动态渲染。

## 八、AI 能力的降级设计

平台定位是「开箱即用」，因此**不依赖任何外部 AI 服务也必须能跑通全流程**。两层降级：

### 1. 大模型层

| 情况 | 行为 | 响应标识 |
|---|---|---|
| 已配置 Key 且调用成功 | 使用 DeepSeek 结果 | `source: "LLM"` |
| 未配置 `DEEPSEEK_API_KEY` | 本地关键词规则引擎 | `source: "RULE"` |
| 调用失败（超时/401/限流） | 回退规则引擎并在文案中标注 | `source: "RULE"` + 「AI 调用失败已降级」 |

### 2. 检索层（RAG）

| 优先级 | 方式 | 响应标识 |
|---|---|---|
| 1 | Chroma 向量语义检索 | `retrievalMode: "VECTOR"` |
| 2 | MySQL ngram 全文索引（`t_knowledge` 的 `ft_knowledge`） | `retrievalMode: "FULLTEXT"` |
| 3 | 关键词模糊匹配 | `retrievalMode: "KEYWORD"` |
| 4 | 无命中 | `retrievalMode: "NONE"` |

> 接入 Chroma 后需要先建索引：管理员调用 `POST /api/ai/index/rebuild`，
> 再用 `GET /api/ai/status` 确认 `chromaReachable=true`。

## 十、性能与安全

| 项 | 做法 |
|---|---|
| 缓存 | 统计与标签云走 Redis 缓存；统计缓存键**带用户维度**，避免多项目隔离下跨用户串数据；写操作主动失效 |
| 缓存降级 | Redis 不可用时静默跳过缓存，连续失败进入 30 秒冷却期，避免每次请求都等连接超时 |
| SQL | 列表页的关联用户信息批量加载，消除逐行查询的 N+1 |
| 限流 | `@RateLimit` 注解 + 内存固定窗口；登录按 IP、AI 接口按用户 |
| 认证 | JWT 无状态；密码 BCrypt 加密；登录失败统一提示，避免用户名枚举 |
| 授权 | 两层：`JwtInterceptor` 鉴权 + `@RequireRole` 注解切面鉴权；数据层再按项目成员校验 |

## 十一、常见问题

**Q：前端 `npm run dev` 报 `'npm' 不是内部或外部命令`**
A：检查 `Path` 环境变量里的 Node.js 目录是否有多余引号或拼写错误。可先用完整路径临时绕过：
`"D:\nodejs\npm.cmd" run dev`。

**Q：登录报「用户名或密码错误」，但库里有账号**
A：密码存的是 BCrypt 密文，无法直接查看。用管理员登录后在「用户管理」中重置。
若库是空的，重启一次后端即可自动创建管理员。

**Q：页面能打开但接口全 404 / 502**
A：后端没起来或端口不对。检查 `docker compose ps` 或本地 8080 是否被占用。

**Q：AI 接口返回 `source: "RULE"`**
A：说明走到了降级路径，不是故障。配置 `DEEPSEEK_API_KEY` 后重启即可启用大模型。
可在「AI 能力状态」页查看连通性。

**Q：上传附件报错**
A：确认 `UPLOAD_DIR` 目录可写。Docker 部署时该目录已挂载为命名卷 `uploads-data`。

**Q：管理员账号被误删/禁用进不去了**
A：直接改数据库，或删除 `t_user` 表中所有 admin 记录后重启后端，会自动重建初始管理员。
